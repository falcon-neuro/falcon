# Events

A processor emits an event when something happens, for example when a channel crosses a threshold on a sample.

An event that comes from a sample holds that sample's header, which is described under [Streams](streams.md). The sample's number in the header places the event in the signal. The time at which the sample reached Falcon is what [`LatencyBenchmark`](../processors/latency_benchmark.md) counts from.

## Spikes

[`SpikeDetector`](../processors/spike_detector.md) emits one {{ api("Spikes") }} event for each sample on which at least one channel crossed its threshold.

The event holds the header of that sample and a mask with one bit per channel, set for every channel that crossed on that sample. Channels that cross on the same sample share one event, so one event can stand for several spikes.

The event marks the crossing of the threshold. The spike's peak comes on that sample or later. The event holds no waveform and no amplitude.

## Ripple

[`RippleDetector`](../processors/ripple_detector.md) emits a {{ api("Ripple") }} event when the power of its input rises above its threshold. One ripple gives one event.

The event belongs to the sample on which the power crossed the threshold. A ripple begins before that sample, because its power has to rise to the threshold first.

The event holds the header of that sample only. The power is one value for the whole stream, so the event names no channel. It says neither how strong the ripple becomes nor how long it lasts.

## TriggerEvent

[`Trigger`](../processors/trigger.md) emits a {{ api("TriggerEvent") }} each time it fires. A `TriggerEvent` stands for a decision to act. Connected to [`PCIeParallelOutput`](../processors/pcie_parallel_output.md), for example, each one starts a pulse.

The event holds the header of the sample whose event made the trigger fire. It doesn't say which channels were named before, or on which samples.

## LevelCrossings

[`LevelCrossingDetector`](../processors/level_crossing_detector.md) emits one {{ api("LevelCrossings") }} event for each sample on which at least one channel crossed its level in the chosen direction.

The event holds what a `Spikes` event holds: the header of that sample and a mask of the channels that crossed on it. The direction is an option of the detector, so the event can mark an upward or a downward crossing.

## ScheduledEvent

[`EventGenerator`](../processors/event_generator.md) emits a {{ api("ScheduledEvent") }} at a fixed rate. The events are generated by a timer, not derived from a signal, so a graph can be tested without acquisition hardware.

A `ScheduledEvent` doesn't belong to a sample, so it has no header. It holds its own number, counted from 1. A processor that needs an event's sample, such as `LatencyBenchmark`, can't take it.
